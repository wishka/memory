# Живой канал (WebSocket)

Сообщения, «печатает», «прочитано» и состав групп приходят без опроса —
по одному WebSocket на телефон. Клиент: Android `net/AndroidNet.kt`
(`OkHttpRealtime`), iPhone `Data/Net/AppleNet.swift`; демо —
`DemoRealtime` (события «шлёт» встроенный демо-сервер).

## Подключение

```
GET wss://<API_URL>/v1/realtime
Authorization: Bearer <access>
```

Токен — тот же, что у API. Истёк (или его нет) — сервер закрывает
соединение кодом 4401; клиент обновляет токен (`POST /v1/auth/refresh`) и подключается
снова. Обрыв — переподключение через 1, 2, 4… с (не реже раза в 5 минут).
Пропущенное за время обрыва клиент добирает обычными запросами
(`GET /v1/chats/{id}/messages`).

## Кадры

Один JSON на кадр, поле `type`:

| type | Кто шлёт | Поля | Что значит |
| --- | --- | --- | --- |
| `message` | сервер | `chat`, `message` (как в API) | Новое сообщение; `message.authorId` — кто, `message.sentAt` — время сервера |
| `typing` | оба | `chat`, `user`, `on` | Печатает (клиент — не чаще раза в 3 с; сервер гасит сам через 6 с) |
| `read` | оба | `chat`, `user`, `upTo` | Прочитал всё, что сервер принял до `upTo` (мс) включительно |
| `group` | сервер | `chat`, `title`, `members`, `admins` | Сменилось название или состав группы |

Пример:

```json
{"type":"read","chat":12,"user":5,"upTo":1800000003000}
```

## Правила сервера

- `read` от человека по запросу на переписку (не друг, запрос не принят)
  не пересылается автору — он не узнает, что прочитали.
- Заблокированных отсекает телефон: сервер о блокировках не знает,
  а их сообщения, `typing` и `read` телефон не показывает.
- В секретных переписках `message.text` — конверт; сервер его не читает.
- Группы — до 200 человек; `typing` в больших группах можно не слать.
